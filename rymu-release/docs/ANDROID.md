## Build and install

For the hosted signed release, set `RYMU_API_BASE=https://rymu.iptvora-server.workers.dev/api/v1` and `RYMU_WEB_ORIGIN=https://rymu.iptvora-server.workers.dev`, then run:

```powershell
./scripts/build-android.ps1 -Abi arm64-v8a -BridgeFiles C:/Users/husse/Documents/rymu/apps/native `
  -TargetCache /opt/rymu/baseline/target -BuildMode release -BuildNumber 77 `
  -ReleaseKeystore C:/Users/husse/Documents/rymu/.local/rymu-android-release-signing/rymu-release.p12 `
  -ReleasePasswordFile C:/Users/husse/Documents/rymu/.local/rymu-android-release-signing/store.pass
```

The pinned upstream script maps build number77 to Android versionCode2077. It stages only product sources, compiles Rust and Flutter release, aligns ZIP entries and signs outside the source checkout with `apksigner`. Both private files above are excluded from source and public artifacts; back them up securely together. Do not regenerate the key for an update. `--ks-pass file:` supplies the keystore password and the same password is reused for the key; passing the same password file a second time as `--key-pass` caused an EOF failure and was removed. Signing/verification succeeded after that correction. Existing output files are not overwritten. The public signing certificate differs from old debug APKs, so existing debug installations may require one manual uninstall/reinstall and sign-in. Do not automatically delete owner data.

## Implementation decisions

Native browser login uses a generated S256 PKCE verifier and exact callback `app.rymu://oauth/callback`. The app checks the original state and compares browser destinations against the configured public origin. The owner verifies a browser code and approves the phone's enrollment proof from the account page. The install's Ed25519 seed, authorization state and rotating tokens are encrypted at rest with Android Keystore AES-GCM. Android backup is disabled. The private seed is briefly available in the app process so the Rust engine can sign the host challenge. A lost device can be revoked in the account. After an ambiguous refresh failure, reuse detection can require fresh sign-in and device approval.

Rymu's three destinations are Devices, Files and Settings. Connect stages the approved host ID and expected engine public key before starting the native viewer. A reconnect obtains fresh authorization before restarting the engine, with up to three attempts after a break. Closing the viewer cancels restaging. A rejected host identity or revoked device stops retry. Rymu preserves the existing engine's gestures, single-display renderer, display selection, file transfer and connection metrics. Direct-touch preference and the session language override are local to the controller-host pair. Auto session language follows the reported Windows UI language if Arabic or English and otherwise uses the phone preference. The Windows keyboard layout is displayed separately when reported.

The text composer sends committed Unicode to the native session. If a Windows field rejects Unicode, the user can switch to physical input or enable the text clipboard and request a clipboard update, then use the Windows app's Paste action. The Android clipboard starts off for each viewer, supports bounded plain text only, and requires both a live engine permission and Android window focus. Transfer uses the upstream Storage Access Framework bridge and the host's authorized transfer scope. The Files destination uses a separate authorized connection. Concurrent interactive viewing and Android transfers, interruption handling, clipboard handoff, and gesture behavior still require native integration tests.

### Local account and revocation smoke

Run `node scripts/test-android-account.mjs` from the workspace root. The verified environment uses Node.js 24.15.0, installed dependencies in `apps/web` and `services/control-plane`, desktop Chromium, and the debug APK in an isolated English-language Android emulator. The default emulator is `emulator-5564`. Set `RYMU_ANDROID_QA_SERIAL` to select a different test emulator and `RYMU_ANDROID_QA_ADB` if ADB is outside PATH. Keep host ports 18787 and 15173 free, or set `RYMU_ANDROID_QA_API_PORT` to choose a different host API port while retaining the APK’s device endpoint.

The test starts the ordinary local Wrangler worker and Vite with a disposable migrated D1 database. It registers a virtual browser passkey, delivers the real service-issued callback through ADB, and checks device proof, browser approval, and entry to the signed-in Devices screen. It then revokes the device from the browser, verifies the removal of its access and refresh credentials, and restarts the app while the same Worker and database are still running. The test creates only its own account and port forwards.

The final ARM64 debug APK passed that full local flow on `emulator-5564`. The app’s first heartbeat after restart received HTTP 401 and the app returned to Sign in. See `artifacts/logs/android-account-emulator-maintained.log`, the independent run in `artifacts/logs/android-account-emulator-wrangler.log`, and the sanitized Worker request log at `artifacts/logs/android-revocation-wrangler-local.log`. The APK and product source were unchanged during the follow-up.

The earlier bare Miniflare fixture passed browser revocation but timed out on the stale Android heartbeat. A separate negative probe reproduced a timeout on heartbeat and refresh POSTs in that fixture. The ordinary local Wrangler listener returned `401 invalid_token`, and the unchanged APK cleared the prior cached account when run against it. The original failure and transport comparison are retained in `artifacts/logs/android-account-emulator-async-adb.log`, `artifacts/logs/android-revocation-transport.log`, and `artifacts/logs/android-revocation-wrangler-cache-check.log`. Physical passkeys, automatic browser-to-app dispatch, and a revoked controller’s direct peer access still require their own tests.
